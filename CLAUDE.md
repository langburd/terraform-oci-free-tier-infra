# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

OpenTofu configurations for Oracle Cloud Infrastructure (OCI) Free Tier resources. Uses reusable modules from the sibling `terraform-oci-free-tier-modules` repo.

Both environments use **OpenTofu** (via `tofu` CLI) with `.tf` file extensions. Terraform 1.14+ broke state uploads to OCI Object Storage due to `aws-chunked` encoding; OpenTofu does not have this regression.

## Structure

- `ddyyconsulting/` and `langburd/` are independent environment directories, each with their own OpenTofu state
- Remote state uses OCI Object Storage S3-compatible backend
- Modules are sourced from `github.com/langburd/terraform-oci-free-tier-modules`
- `.opentofu-version` at repo root pins the OpenTofu version (`latest-stable`)

## Commands

- Format: `tofu fmt` (runs automatically via pre-commit)
- Validate: `tofu validate` (run from within an environment directory after `tofu init`)
- Lint: pre-commit hooks handle `terraform_fmt`, `terraform_tflint`, `terraform_docs`, and YAML validation
- Run all pre-commit checks: `pre-commit run --all-files`
- CI: PRs to `master` run `.github/workflows/pre-commit.yml`, which installs OpenTofu, tflint, and terraform-docs, then runs `pre-commit/action` (the same hooks as local)

## Git Workflow

- Never push directly to `master` — always create a feature branch and open a PR
- PRs merge into `master`

## Non-Obvious Gotchas

- **State upload checksum (set before every run)**: The AWS SDK behind the S3 backend forces `aws-chunked` encoding for default data-integrity checksums, which OCI Object Storage rejects with `501 NotImplemented: AWS chunked encoding not supported` on state upload. `skip_s3_checksum = true` in the backend is not enough. Export these in your shell before running `tofu`:
  ```bash
  export AWS_REQUEST_CHECKSUM_CALCULATION=when_required
  export AWS_RESPONSE_CHECKSUM_VALIDATION=when_required
  ```
- **State upload failures (chunked encoding)**: OCI Object Storage doesn't support AWS chunked transfer encoding. This is why both environments use OpenTofu instead of Terraform 1.14+. If `tofu apply` still fails to save state with `api error NotImplemented: AWS chunked encoding not supported`, it writes the state to `errored.tfstate` locally. Push it manually with:
  ```bash
  oci os object put \
    --namespace <namespace> \
    --bucket-name <bucket> \
    --name <key> \
    --file errored.tfstate \
    --profile <profile> \
    --force
  ```
  The `use_lockfile = false` backend setting reduces (but does not eliminate) how often this occurs.

## Conventions

- OpenTofu version >= 1.8.4, OCI provider ~> 8.0
- Do NOT edit text between `<!-- BEGIN_TF_DOCS -->` and `<!-- END_TF_DOCS -->` markers — these are auto-generated by terraform-docs
- Run `tofu validate` before committing changes
- OCI authentication uses profile-based config from `~/.oci/config` — the `oci_profile_reader` module parses this
- Tags are NOT applied via provider `default_tags` (the provider block has none). In `ddyyconsulting/main.tf` a `locals.default_tags` map (Environment, GitRepo, ManagedBy, Owner) is passed explicitly to each module as `*_freeform_tags` args. `langburd/` defines no `default_tags` local and sets bespoke per-module tags instead.
- Dependency updates: Renovate (`renovate.json`) groups and auto-merges minor/patch updates for GitHub Actions, pre-commit hooks, and Terraform providers & modules

## Module Source Format

Modules use [terraform-module-releaser](https://github.com/techpivot/terraform-module-releaser) which creates per-module orphan tag commits. Each tag (e.g., `oci/budget/v1.0.0`) points to a commit containing only that module's files at root level — no subdirectory.

Correct source format:

```hcl
source = "git@github.com:langburd/terraform-oci-free-tier-modules.git?ref=oci/<module>/vX.Y.Z"
```

Do NOT use `//oci/<module>` subdir notation — the subdir does not exist at the tagged commit.
